# 单会话全生命周期：记忆外置设计（P5）

> 用户拍板（2026-10-05）：秘书模型便宜，浪费得起，上下文压缩可接受；
> 目标是**一个会话覆盖项目完整生命周期**——但一次上下文肯定装不下，
> 所以关键不是「留住上下文」，是「**涵盖住所有记忆**」。

## 核心原则：session 是窗口，文件是记忆

```
session（秘书）= 一个可替换的窗口，烂了/满了/压缩了都不重要
                 ↑ 窗口里的东西随时可以丢
文件集          = 项目的全部记忆，canonical，永远完整
```

**「单会话全生命周期」的正确含义**：不是让一个 session 的 token 无限增长（那必然撞上 64-128k 衰减和拒答），而是**这个 session 无论被压缩、被清空、被重启多少次，都能从文件集完整恢复现场，接着干**——对用户来说它就是「同一个会话」。

## 记忆分层（从快到慢，全部已存在或在用）

| 层 | 载体 | 存什么 | 恢复方式 |
|---|---|---|---|
| 1. 热 | 当前 session 上下文 | 正在做的事 | 窗口内自然有 |
| 2. 温 | `_tickets/handoff.md`（frontmatter 结论层） | 下一件动作、HEAD、预算、在飞子会话 | 新窗口先读这层就能开工 |
| 3. 状态 | `_tickets/state.md` | 口径真源表、已统一、未决、上次根因 | 跨口径单开工前必读 |
| 4. 决策 | `_tickets/decisions.md`、`queue.md`、`progress.md` | 待定项、顺序、逐单结果 | 无人托管时接管 |
| 5. 档案 | `_tickets/done/`、`_receipts/`、`_tickets/req-*.md` | 全部历史工单与回执 | 按需 grep，不常驻 |
| 6. 长程 | `~/.dsh/foreman-insights/`（usage/analysis） | 跨项目使用数据与迭代依据 | 每期分析时读 |
| 7. 召回（可选） | MemOS 记忆系统（本机已装，skill 目录可见） | 对话级语义记忆 | **待验证后接入**——验证通过前不作依赖 |

## 规则（写进 SOP 的部分）

1. **凡记忆必落文件**：任何「以后会用到」的信息（口径、决策、约定、根因、成本数），当场写进对应层的文件，**不许只留在会话里**。留在会话里 = 注定会丢。
2. **压缩不丢人**：上下文压缩（compaction）发生时，被压掉的内容必须已经在文件里——压缩只压窗口，不压记忆。这条靠第 1 条保证。
3. **恢复靠读不靠记**：任何窗口（新会话/压缩后/换模型）开工前的固定动作是读 handoff frontmatter + state.md，**不从会话残片里拼记忆**。
4. **秘书便宜是设计前提，不是缺陷**：窗口可以随便换、随便压缩，因为成本大头从来不在窗口——在文件集和 foreman 的判断里。

## 与已有机制的关系（不新造轮子）

这套设计的全部载体在 v0.3-v0.6 已逐个落地：req 文件、state.md、handoff frontmatter、decisions/queue/progress、insights 台账。**本文件只是把它们收拢成一个原则**：记忆外置。唯一新增的技术验证项是第 7 层（MemOS 召回），验证路径：给秘书一句「查一下我们上周对 XX 的决定」，看召回质量；不行就砍掉这层，文件集自足。
