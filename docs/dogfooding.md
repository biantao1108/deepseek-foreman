# Dogfooding：用自己的工单流程跑出来的第一批实证

2026-10-01 凌晨，本项目用它自己的工单托管流程（`skill/deepseek-foreman/`）完成了第一批真实工单：派单 → 施工 → 异族只读审查 → Lead 逐条核实 → 修复回单。这份记录是公开版，绝对路径与私有路由名都已脱敏，路由一律写成 `vendorX/modelY` 占位。

本文档占位映射（vendorX/modelY）仅本文档内有效。

## 流程

每张工单都走同一套：

1. **派单**：Lead 把活写成工单落到 `_tickets/doing/`，指定施工路由、推理档位、边界，以及可直接复制的验收命令。
2. **施工**：工人模型只按工单改文件；回执写回 `_receipts/`，每条验收都贴真实命令和原样输出。
3. **异族审查**：换一家厂商的模型做只读审查，自己独立重跑验收命令，按高 / 中 / 低分级给发现。
4. **逐条核实**：Lead 对每条发现做「成立 / 不成立」裁决并写清依据；成立的要么并进后续单，要么当场闭环。

## 这条流水线实际抓到了什么

- **出厂示例的 `~` 展开坑**：`rolesFile` 不展开 `~`，注释里的示例会让用户在 cwd 下建出一个字面名为 `~` 的目录。这是纯代码审查才能从示例反推出来的用户级坑。
- **TOCTOU 方向错误**：先读内容后 stat、把新 mtime 配旧内容记下来，会从此永久漏掉一次热更新。只有把「读」与「stat」的先后当成契约来审，才会注意到。
- **回退验证（mutation testing）**：T102b 修完 5 条后，工人逐条把修复临时改回旧写法、确认对应新自检真的失败、再改回来。这证明新断言不是「永远为真」的摆设。
- **自检数长在真实缺陷上**：这条线跑下来自检从 20 → 42 → 62，每次新增都对应一个被抓到的具体问题。
