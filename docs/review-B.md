# deepseek-foreman 第三方盲审报告 B（产品与成本落地）
评审：MiMo-V2.6-Pro @ 2026-10-01
（盲审原文存档；来源为独立评审子代理，Lead 未修改内容）

## 总评
deepseek-foreman 是目前开源里少有的「把经理纪律写进运行时」的 dsh 原生工单系统：配置外置+热更新、pick_route 四条硬约束、subagent_readonly 物理只读、回执/验收/逐条核实闭环，工程细节（TOCTOU、悬空软链、bundle insert: 坑）经得起推敲，110 项自检质量不低。但它对外主打的「又省又好」里，「省」恰恰是全项目唯一没被测量的部分：实测数据只记了施工子会话的 token，Lead（最贵模型）的派单/验收/核实用量、审查真实路由、美元成本全部缺账，而审查实际跑在 Lead 模型上、K3 自写的活存在审查空洞，成本三角并不闭合。小白三步把全程最难的手工活（allowedModels 白名单 YAML）藏进了第 1 步，故障速查仅 4 行，「装完就用」目前只对作者本人成立。理念层仍是 2024 式串行 manager-worker，缺 effort scaling、成本归因、并行 fan-out 与 checkpoint 这些 2025-2026 已验证要素。结论：质量闭环可信、成本主张不可核账；v0.3 若只做一件事，做「每单成本台账 + 工单分级」。

## 主题 1：真实成本与效果

### 优点
1. 省钱机制的定性主张有流程支撑，且与业界结论同向：施工 token 全部落在便宜模型，Lead 上下文只放工单/回执/审查意见。与 Anthropic 多智能体研究系统「子代理独立上下文压缩、主 agent 只看精华」同向。
2. 口径诚实，不编数字：明确「未做严格 A/B 对照实验，不给百分比承诺」。
3. 质量闭环真实抓到了东西：~ 展开坑、TOCTOU 方向错误、mutation testing、两起 live 才炸的事故、1 条高危泄露拦截。审查 20+ 发现、约 19 成立、1 驳回。
4. 审查成本效益极好：验证类 0.6-1.6 万 token/次；按上游公开数据反推审查约占施工成本 5%，却拦下高危泄露。
5. 兜底不靠自觉：pick_route 硬约束会真拒、只读审查是运行时工具面裁剪、110 项自检覆盖失败面。

### 问题
- [高] Lead 用量完全没进账（README.md:155 只有施工口径；progress.md 0 处花费）。施工 token 便宜到可忽略，真正决定「省不省」的是 Lead 配额消耗，恰是唯一没测的部分。→ 每单记 Lead turn/施工/审查/花费 + 3 张单 A/B。
- [高] 「Lead 不读代码」与 SOP 矛盾（SKILL.md:8 vs :127/:106）。→ 外包 fact-check 或改口径。
- [高] 异族审查实际跑在 Lead 模型上，成本三角不闭合；K3 自写活无审查（cordis.patch.yml:24-27、README.md:114/148）。→ 默认「异族便宜+提示词只读」，物理只读留高危单。
- [中] 小任务被全流程拖贵，缺 effort scaling（T302/T306 三五行改动也走全流程）。→ trivial/normal/critical 三级。
- [中] 「验证类调用」口径不明；[中] 无成本归因与预算强制；[中] 样本只报喜：重做率约 10%（T102b/T202b）未写。
- [低] fork 与「一单一会话」边界不清；[低] 工单总数口径（19 vs 23 张）。

## 主题 2：小白体验

### 优点
1. 最易错三件事已自动化（skill 自动安装/角色表模板/不炸启动）。2. doctor 单入口自检 + 坏文件保留旧表。3. 热更新免重启、TOCTOU 顺序当契约处理。4. 降级路径齐备。

### 问题
- [高] 小白三步第 1 步藏掉全程最难的手工活：allowedModels 白名单要手改 YAML（README.md:53/92-95）。→ setup 向导代写白名单。
- [高] 角色表路由名无处可抄（roles.example.yml 占位）。→ setup 列出可用 provider/model 供复制。
- [中] 故障速查仅 4 行；[中] 三种生效语义并存（新会话/重启/热更新）易漏；[中] 「帮我配 foreman」无确定性脚本兜底。
- [低] 文档 macOS 视角；[低] peerDep 钉 rc；[低] 「≤10 分钟」无实测。

## 主题 3：业界对比

### 别人没有的
1. dsh 原生按次换模型（上游要外部 CLI + dispatch.sh）。2. 物理只读审查硬于上游（进程参数层 vs 运行时工具面裁剪）。3. 配置外置+热更新+引导态+四条硬约束产品化。4. 文件契约+「回执是说法不是证据」与 Anthropic 2025 结论同向。5. 流程命中率与上游互证（成立率≈上游 87%；重做率≈上游 1/10）。

### 问题
- [高] 成本透明度落后业界一整个身位，落后点正是自己的卖点。上游公开美元账、Anthropic 公开 15× token 结论、Kimi 生态要求成本聚合。
- [中] 拓扑仍是 2024 式串行，缺 2025-2026 三要素（effort scaling/并行 fan-out/checkpoint）。
- [中] 「便宜模型干活」不是壁垒（Agentless 流水线更便宜）；卖点应移到「可验证的质量与成本闭环」。
- [中] 外置 skill 对模型换代敏感，编排正被吃进产品层；建议纪律更多下沉到插件可执行约束。
- [低] 失败两次/预算上限纯文字；[低] 上游两件好东西没移植（首次试跑小工单、模型体感表）。

## 给 v0.3 的建议清单（按优先级）
1. 成本台账（每单 Lead turn/施工/审查/花费 + 3 单 A/B）
2. 工单分级 + effort scaling（trivial/normal/critical）
3. 审查路由解绑 Lead（默认异族便宜+提示词只读，物理只读留高危）
4. 低成本口径修正（「Lead 不读代码」表述、deny 夸大、验证类口径、重做率）
5. setup 向导（代写白名单、预填真实路由、首次试跑小工单）
6. 故障速查扩 10 行，与 doctor hints 对应
7. doctor 提示生效语义
8. 无人托管可执行化（失败两次/预算上限做成检查 + checkpoint）
9. 并行 fan-out 规则与 workflow 模板
10. 文档面收尾（Windows、「≤10 分钟」标注、peerDep 放宽）

如果只做一件事追平业界：每单成本台账 + 工单分级。（第二候选：一键 setup 向导。）
