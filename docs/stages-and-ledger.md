# 五个阶段与 token 台账

> 目的：**不设预算、不猜成本，只如实计数**。有了计数，成本自己会算；没有计数，任何预算都是猜的。

## 阶段词表（命名以此为准）

| 阶段名 | 中文 | 执行者 | 职责 | 台账列 |
|---|---|---|---|---|
| `session` | 会话（秘书） | 最便宜档模型 | 与用户对话、追问澄清、把大白话整理成需求包 | `session_tokens` |
| `foreman` | 决策层 | 高档模型 | 分析、拆单、派单、亲自重跑验收、逐条核实 | `foreman_tokens` |
| `worker` | 施工层 | 便宜档模型 | 实现代码/文档，跑工单里的验收命令 | `worker_tokens` |
| `reviewer` | 审查层 | **异族**模型 | 只读审查找真问题 | `reviewer_tokens` |
| `report` | 回传 | 由 `session` 执行 | 汇总各阶段结论 → 汇报给用户 | 计入 session |

**命名说明**：
- `foreman` = 工头 = 产品名 = 角色表里的 `lead` 角色（**role key 保持 `lead` 不改**，避免配置断裂；文档统一称 foreman）
- `reviewer` 必须与 `worker` 异族，否则 `pick_route` 硬拒
- `report` 不是新模型，是 `session` 的一次动作；但**它是必经步骤**——不回传，用户看不到结果、秘书无法追问、下一轮会丢产出

## 台账格式（每张工单一行，只记数不设限）

| 时间 | 工单 | session | foreman | worker | reviewer | report | 结果 | 问题标记 |
|---|---|---|---|---|---|---|---|---|
| 2026-10-04 12:00 | T037-对齐口径 | 12.3万 | 88.1万 | 见面板 | 见面板 | ✅ | done | ok |

> **台账定位（2026-10-05 用户拍板）：只做统计参考，不要求精确。**
> `worker` / `reviewer` 两列由人从 dsh 面板抄个大概即可，允许四舍五入到万位，标「参考」；
> 目的是看量级（判断 vs 实现哪边大），不是对账。模型仍然不估算、不编造——它读不到的就空着。
> 依据（2026-10-04 源码实证）：`list_agents` 的 output schema 是**闭集**（`kind/id/label/status/parent/depth`），
> **不含 token 字段**；子代理 tokenUsage 投影只进浏览器 UI（`dsh-client-ui-subagent/lib/client.js:233`），
> **模型侧没有任何工具能读到**。所以这两段的精确数字由**人在 dsh 子代理面板看**，
> 模型**不估算、不编造**——这是「回执是说法不是证据」在计量上的延伸。

> 单位：万 token。取自 `pick_route cost_session=recent`（服务端真实计量，不是估算）。

## 累计与成本核算

- **累计**：每期末按阶段求和 → 得到「本项目/本周期各阶段花了多少」。
- **成本**：各阶段 token × 该模型单价 = 分阶段成本。单价随厂商变动，**记账只存 token，单价在核算时现取**——这样 token 数永远是可核对的事实。
- **一句话结论**：贵模型的 token 花在 `foreman`（判断），便宜模型的 token 花在 `worker`（实现）。**看这个比值就知道钱花在哪了**，比任何预算数字都有用。
- **各阶段数字的来源分工**：`session` / `foreman` 模型自己读得到（`pick_route cost_session=recent` 读当前会话）；`worker` / `reviewer` **模型读不到，去 dsh 面板看**。这条分工是本产品的已知边界，不是待修项。

## 为什么取消「预算闸」

原来的预算闸（单张 500 万 token、Lead 200 轮）是拍脑袋的数字，单位也不是成本量。改成：
- **不设上限、不设熔断**——只如实计数。
- 想要熔断时，用**可观测信号**而不是计数器：连续 2 张单没验收通过（无进展）、同一口径第 3 次被改（修补链）、你明确说的时间点。
